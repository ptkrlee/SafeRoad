# 신청내용 수정과 숫자 비밀번호

관리자 명단의 ‘신청내용 수정’에서 이름·전화번호·주소·인원·입금자명을 고칩니다. 지난 회차의 공란은 그대로 둘 수 있으며 원본 운영자료와 당시 동의 사본은 유지합니다. 기존 신청의 변경용 비밀번호를 새로 설정하거나 분실한 비밀번호를 재설정할 수도 있습니다.

## 한 번만 설치

1. Vercel 환경변수에 기존 완보자 사진방에서 쓰는 서버 전용 `SUPABASE_SECRET_KEY`가 있는지 확인합니다. `NEXT_PUBLIC_` 이름으로 만들지 않습니다. 기존 값이 있으면 새로 추가할 필요가 없습니다.
2. `신청내용수정-설치.sql` 전체를 Supabase SQL Editor에서 실행합니다. 기존 운영 사이트의 08 단계와 09 단계를 함께 적용하며 기존 명단을 삭제하지 않습니다. 03~06과 갤러리를 설치한 현재 사이트용입니다.
3. Vercel 최신 배포가 Ready가 되면 관리자와 신청 페이지를 새로고침합니다. 새 신청서에 숫자 비밀번호와 확인란이 나타나는지 확인합니다. 기존에 열어둔 신청서는 새로고침해야 최신 동의문과 비밀번호를 적용합니다.

설치 전에는 종전 신청 접수가 유지됩니다. 설치 후 서버 키가 없으면 비밀번호가 빠진 신청을 저장하는 대신 설정 준비 안내를 표시합니다. 초기 SQL 전체를 다시 실행하지 않습니다.

## 참가자 이용

- 홈 신청 영역과 신청 완료 화면의 ‘신청내역 확인·변경’을 누릅니다. 직접 주소는 `/application-edit`입니다.
- 현재 신청 전화번호와 숫자 4~12자리 비밀번호로 조회합니다. 같은 전화번호·비밀번호로 신청한 내역을 함께 표시합니다. 전화번호를 바꾸면 이후에는 새 번호로 조회합니다.
- 조회 권한은 20분 동안 유지됩니다. 조회 종료 버튼으로 바로 닫을 수 있습니다.
- 체험 시작 전의 참여 예정 신청만 직접 수정합니다. 신규 접수가 마감된 회차의 인원 증가는 막고 정원은 서버에서 다시 검증합니다. 회차 변경·취소·비밀번호 분실은 사무국 문자 연락으로 처리합니다.
- 기존 신청에는 비밀번호를 자동 배정하지 않습니다. 관리자가 참가자 요청을 확인한 뒤 설정해주세요.

## 인원과 금액

인원이 바뀌면 기존 1인 단가(확인되지 않으면 현재 참가비)를 기준으로 신청 참가비를 다시 계산합니다. 이미 입금 확인된 신청은 ‘인원 변경·금액 재확인’으로 표시하며 관리자가 실제 입금·추가 입금·환불을 확인한 뒤 입금 확인을 다시 처리합니다. 금액 재확인 대상에게 기존 전액 미입금 독촉 문구를 자동으로 적용하지 않습니다. 실제 송금·환불은 실행하지 않습니다. 취소·환불 처리 중인 신청의 인원은 직접 변경하지 않습니다.

## 보존과 인증

- 수정 전후 정보·처리 주체를 관리자 이력에 기록하고 원래 개인정보·사진 동의 사본을 바꾸지 않습니다. 다른 화면에서 먼저 수정했으면 새로 조회하도록 안내합니다.
- 비밀번호 원문은 저장하지 않습니다. 소금값을 붙인 scrypt 인증값은 private 테이블에 보관하며 명단·엑셀·처리 이력에 포함하지 않습니다.
- 조회 시도는 전화번호별 15분에 5회, 접속 주소별 15분에 30회로 제한합니다. 성공하면 해당 전화번호의 실패 횟수는 초기화합니다.
- 조회 쿠키는 HttpOnly·SameSite=Strict이며 운영 환경에서는 Secure를 적용합니다. 접수번호·인증 버전만 서명해 담고 전화번호나 비밀번호는 담지 않습니다. 비밀번호 재설정 시 기존 조회 권한은 무효화됩니다.
- 인증값은 신청 기록 삭제 시 함께 삭제됩니다. 기존 1년 보관·관리자 수동 파기 원칙은 유지합니다.
