# 공식 갤러리와 완보자 사진방

공식 갤러리 `/gallery`는 누구나 열람하지만 다운로드 버튼과 원본 제공은 하지 않습니다. 표시된 이미지의 저장이나 화면 캡처까지 완전히 막는 방식은 아닙니다. 완보자 사진방 `/gallery/participants`는 체험 날짜 8자리(예: `20261114`)를 입력해 해당 회차 사진을 열람·다운로드합니다. 회원가입은 필요 없습니다. 날짜 코드를 아는 사람이 함께 이용하는 방식이며 개인별 참가 여부를 확인하지 않습니다. 입장 상태는 4시간 유지됩니다.

## 4단계를 완료한 프로젝트의 이번 변경

`supabase/05-public-gallery-view-only.sql`만 추가 실행하여 `5단계 완료`를 확인합니다. 공식 사진의 원본 Storage 접근도 차단하며 완보자 사진방의 다운로드는 유지합니다. 기존 신청별 동의 사본은 변경하지 않습니다. 04 또는 가져오기를 다시 실행하지 않습니다. 이전에 발급한 원본 링크는 최대 60초 후 만료됩니다.

## 처음 두 갤러리를 설치하는 프로젝트

이미 3단계 설치와 신청자 가져오기를 마쳤다면 `supabase/04-public-gallery.sql`만 SQL Editor에서 실행합니다. `4단계 완료`가 나오면 성공입니다. 초기 SQL이나 03을 다시 실행하거나 기존 명단을 다시 가져오지 않습니다. 기존 신청·기존 동의문 사본은 보존됩니다. 04 다음에는 05를 실행합니다. 최신 코드 배포 후 04 적용 전에는 새 신청이 잠시 차단됩니다.

완보자 사진방에는 서버 전용 키가 추가로 필요합니다.

1. Supabase → Settings → API Keys → Secret keys에서 키를 복사합니다. `sb_secret_`로 시작하는 키입니다.
2. Vercel → 프로젝트 Settings → Environment Variables → Add Environment Variable에서 Type은 **Secret**, Key는 **SUPABASE_SECRET_KEY**, Value는 복사한 키, Environment는 **Production**으로 저장합니다.
3. 기존 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_ANON_KEY`는 유지합니다. 비밀 키를 이 두 공개 변수에 넣거나 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. 키를 채팅·GitHub·화면 캡처로 공유하지 않습니다.
4. Vercel에서 Production을 Redeploy하고 Ready가 된 뒤 관리자 화면을 새로고침합니다.

이 키는 서버에서만 사용합니다. 브라우저에 전달하지 않으며 날짜 입장코드 확인과 해당 회차의 사진 제공에 사용합니다. 서버 설정이 없으면 완보자 사진 업로드와 사진방 입장을 차단합니다. 공식 갤러리는 기존 공개 키로 사용할 수 있습니다.

## 사진 게시

1. `/admin`의 사진 갤러리 관리를 펼칩니다.
2. 회차와 **공식 공개 / 완보자 사진방** 중 게시 위치를 선택합니다. 사진방 입장코드는 회차 날짜에서 자동 결정됩니다.
3. 설명을 적고 JPEG·PNG·WebP 사진을 선택합니다. 한 장당 10MB, 한 번에 최대 10장입니다. 이름·전화번호를 설명에 쓰지 않습니다.
4. 사진 속 식별 가능한 모든 인물에게 **선택한 게시 위치의 촬영·공유·다운로드 범위**에 동의했는지 확인하고 확인란을 체크합니다. 대표 신청자의 동의만으로 일행 전체가 동의한 것으로 간주하지 않습니다.
5. 업로드·게시 후 해당 갤러리에서 사진 한 장의 열람·다운로드를 확인합니다. 완보자에게는 현장에서 체험 날짜 8자리 입장코드를 안내합니다.

파일은 관리자 브라우저에서 Supabase Storage로 직접 업로드하며 임의 ID로 저장합니다. 목록에는 긴 변 720픽셀 이하의 미리보기를, 완보자 사진방의 다운로드에만 원본을 제공합니다. 원본의 위치 등 부가정보를 공유하지 않으려면 업로드 전에 제거합니다. 자동 얼굴 가림·동의 판별 기능은 없습니다. 게시 위치 변경은 제공하지 않으므로 다른 범위에 게시하려면 동의를 다시 확인하여 별도로 올립니다.

## 두 가지 선택 동의

신청 시 완보자 사진방 게시·다운로드와 공식 공개 갤러리 게시·열람을 각각 선택합니다. 둘 다 동의하지 않아도 신청할 수 있습니다. 날짜 코드는 추측·전달될 수 있다는 안내도 동의문에 포함합니다. 홈페이지 외 SNS·광고 사용은 포함하지 않습니다.

이전 카페 공유 동의나 네이버폼 포괄 동의를 새 두 범위에 소급 적용하지 않습니다. 기존 가져오기 3건·4명의 별도 사진 동의는 기록 없음이므로 게시 전에 인물별로 확인합니다. 이전 범위 동의는 관리자 명단에서 재확인 대상으로 표시합니다. 이미 다운로드된 사본을 모두 회수할 수는 없습니다.

## 비공개·삭제·보유 기간

비공개 처리는 새로운 열람·다운로드를 차단합니다. 이미 발급된 링크는 최대 60초 이내에 만료됩니다. 파일 삭제는 먼저 비공개 처리하고 Storage 파일을 제거한 뒤 사진 기록을 삭제합니다. 실패하면 비공개 기록이 남아 재시도할 수 있습니다.

사진의 제공 기한은 해당 회차의 가장 이른 신청일 + 1년을 넘지 않게 계산하며 신청 기록이 없으면 업로드 준비일 + 1년 이내입니다. 원본 응답에 수정 표시가 있거나 최초 신청일이 불명확하면 관리자가 실제 보유 만료일을 확인하여 더 일찍 삭제합니다. 만료 시 접근은 차단하지만 물리적 자동 파기는 아직 없으므로 기간 만료 자료는 관리자가 삭제해야 합니다. 관리자 사진 목록은 최신 100장입니다. 이전 자료는 Supabase Storage와 데이터베이스에서도 관리합니다. 사진 작업의 관리자 UID·시각·게시 범위를 이력에 기록합니다.

## 검증 범위

로컬 PostgreSQL 엔진에서 관리자 권한, 공개·완보자 사진의 행 및 파일 접근 제한, 게시 승인·비공개·만료·삭제 순서, 기존 동의 보존을 검증했습니다. 입장 토큰의 변조·만료·서명 검증도 테스트했습니다. 실제 Supabase Storage와 Vercel 연동은 위 설정 후 사진 한 장을 올려 확인해야 합니다.
