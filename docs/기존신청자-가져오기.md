# 기존 네이버폼 신청자 가져오기

운영 중인 프로젝트에는 `supabase/03-consent-import.sql`만 추가 실행합니다. 초기 설치 스크립트(schema.sql, 01, 02)는 다시 실행하지 않습니다. 추가 SQL은 기존 신청을 지우거나 기존 동의를 새 동의로 바꾸지 않습니다. 기존 정책은 새 3일 전 환불 안내와 개인정보·사진 동의문으로 갱신되고 정책 버전이 증가합니다. 기존 신청자가 동의한 당시 문구는 각 신청의 동의문 사본에 남습니다.

## 순서

1. 추가 SQL을 실행하고 `3단계 완료`를 확인합니다.
2. Vercel에서 최신 코드 배포가 Ready인지 확인한 뒤 관리자 화면을 새로고침합니다.
3. ‘기존 네이버폼 신청자 엑셀 가져오기’를 펼칩니다.
4. 등록할 회차를 확인하고 원본 .xlsx 파일을 선택합니다. 회차를 바꾸면 미리보기가 초기화됩니다.
5. 이름·연락처·인원과 원본 일시 표시를 확인한 뒤 ‘가져오기 확정’을 누릅니다.
6. 신규·중복 건수 결과를 확인하고 새로고침해 통합 명단을 확인합니다.

엑셀은 관리자 브라우저에서 해석합니다. 전체 원본 파일을 공개 저장소·공개 링크에 저장하지 않습니다. 로그인한 관리자만 정규화된 행을 등록할 수 있으며, 서버에서도 형식·권한·정원·중복을 재검증합니다.

## 보존하는 것과 추정하지 않는 것

- 파일의 응답일시를 접수 기록 시각으로 저장하고 `(수정)` 표시가 있으면 함께 기록합니다. 수정 응답의 시각을 최초 신청·동의 시각이라고 단정하지 않습니다. 최초 신청일이 필요하면 원본 네이버폼 기록과 대조합니다.
- 이름·시군구·연락처·총인원과 기존 개인정보 동의 응답, 취소·환불 안내 확인 응답을 보존합니다.
- 새 홈페이지의 개인정보·환불 정책에 다시 동의한 것으로 간주하지 않습니다. 기존 참가자의 환불 등은 당시 안내 조건을 먼저 확인하고, 변경이 필요하면 별도 안내합니다.
- 별도 사진 동의 열이 없는 기존 신청은 ‘사진: 기록 없음’으로 표시합니다. 원래 포괄 동의에 사진 공유가 언급됐더라도 새 선택 동의에 동의한 것으로 바꾸지 않습니다.
- 입금 내역이 없으면 입금 미확인, 입금자명 열이 없으면 ‘원본 미기재’로 남깁니다. 실제 은행 확인 후 입금 확인을 처리합니다.
- 대표 신청자의 사진 동의는 일행의 사진 동의가 아닙니다. 기록 없음·비동의 신청자는 촬영·공유 전에 개별 확인해야 합니다.

## 중복·정원

같은 자료를 다시 가져와도 이미 등록된 행은 중복 추가하지 않습니다. 이름·전화번호가 같고 원래 또는 현재 회차가 같은 신청이 있으면 기존 신청으로 판단해 건너뜁니다. 날짜를 변경했거나 취소한 신청도 원래 파일을 다시 가져왔다고 복제하거나 되살리지 않습니다. 건너뛴 신청이 실제 다른 신청이라면 원본과 명단을 대조해 별도 확인합니다.

정원 초과나 잘못된 행이 있으면 해당 요청 전체를 취소합니다. 기존 신청을 삭제하거나 정원을 자동 확대하지 않습니다. 회차를 잘못 선택한 경우에도 자동 판단하지 않으므로 확정 전에 회차를 확인해야 합니다.

## 환불과 동의 변경

- 새 정책의 환불 신청 마감일은 체험일에서 달력상 3일 전입니다. 10/23 → 10/20, 11/14 → 11/11, 11/21 → 11/18.
- 참가자 취소는 이체수수료 500원 공제(농협 0원), 주최 측 취소는 수수료 없이 전액 환불 기준을 유지합니다.
- 마감 후 참가자 취소의 환불 여부와 마감 시각은 아직 확정하지 않아 ‘사무국 문의’로 안내합니다. 은행 환불과 마감 판정은 자동 실행하지 않습니다. 문자로 받은 요청의 시각을 기준으로 운영자가 확인합니다.
- 개인정보 보관은 신청일로부터 1년입니다. 자동 파기 기능은 아직 없으므로 운영자가 기간 만료 자료와 연결 기록을 파기해야 합니다.
- 개인정보 동의는 필수, 사진 촬영·비공개 공유 동의는 선택입니다. 공개 홍보 이용은 포함하지 않습니다. 공유처를 안내하고 동의 범위를 확인하기 전에는 게시하지 않습니다.
- 여행자보험 가입 목적만으로 홈페이지에서 주민등록번호를 수집하지 않습니다. 보험사 요구 항목·수집 근거·수집 주체·안전한 전달 방식이 확인되면 별도 절차를 정합니다.
